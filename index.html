SCDBench

A Benchmark for LLM-Based Smart Contract Decompilers

Kaihua Qin1Dawn Song2Arthur Gervais3

1 University of Warwick2 UC Berkeley3 University College London

Paper Code Dataset Cite

SCDBench evaluates LLM-based smart contract decompilers using 600 real-world Ethereum contracts and 227,383 semantic checkpoints. Frontier models achieve higher semantic consistency than the open-weight baseline, while GLM-5 with reasoning outperforms its instruct variant on this metric (20.7% versus 17.7% after repair). One-step compiler-guided repair improves compilation, ABI recovery, and semantic consistency for every model. However, structural success does not ensure faithful behavior. Repaired GPT-5.3-Codex leads compilation and ABI recovery, while repaired Claude Opus 4.7 achieves the highest overall semantic consistency. Even the best setting perfectly recovers only 42 of 600 contracts (7.0%) under the benchmark's checks. These main findings persist on a second 600-contract sample, highlighting both the value of compiler feedback and the need for stronger semantic recovery.

Evaluation protocol

  1. 1. Format

    Complete Solidity and compiler settings.

  2. 2. Compilation

    A valid compiled contract.

  3. 3. ABI

    Recovered public function signatures.

  4. 4. Semantics

    Matching returns, reverts, logs, and storage changes.

Scores are cumulative. One-step repair uses compiler feedback on format-valid outputs that fail compilation. Contracts are sampled from source-verified Ethereum deployments. Passing finite checkpoints does not prove equivalence over all executions.
